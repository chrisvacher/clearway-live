# Foundation practice and seed data

`supabase/seed.sql` creates the permanent practice engagement and the fictional Riverside Church Wayfinding engagement with eight people, including one scribe. Names, emails and church records are fictional. Stable seed ids support repeatable tests, while `ON CONFLICT DO NOTHING` preserves existing edits and soft-deleted history. External Team Hub and CORE ids remain null. Existing Clearway admins are assigned as lead where a seed engagement has no lead.

Seeds are deliberately separate from schema migrations. Local setup runs `npm run db:seed` after starting and resetting the local stack. This command refuses a non-loopback database URL. CI replays schema/role tests without seeds, then loads the seeds twice and tests their actual contents and native practice Auth. Production seeds run only against the Live project after PR 7 is merged.

`/practice` opens the permanent room. A phone supplies its name and a random device proof, without email sign-in or a code. The service-only guest RPC accepts this permanent practice id and, since November 9, team workshops with admin-enabled open joining. Other engagements require the attendee email/code, confirmed link or facilitator approval. Practice identities use pseudonymous per-device emails under `practice.clearway.invalid`, exchange native Supabase OTP sessions without sending email, and use the same room-session proof checks. Global anonymous Auth remains disabled. See [room sign-in](room-sign-in.md) for workshop open joining.

The control/setup surfaces still require a listed Clearway Google account. Practice participants cannot read setup, the roster, Clearway users or invite batches. Fictional `.example`, `.invalid` and `.test` addresses cannot receive invitation batches. To test email sign-in with a real phone, replace a fictional Riverside attendee email with your own, or add a real test attendee, then review and send that personal invite.

# Reset
Reset practice room also puts away every AI record of the practice engagement (`private.ai_reset_room`): word combines, groups and their members, summaries, every grid merge, deleted for good so the AI can merge those reasons again (including pre-mortem reasons "merged by AI"), the session runs (a run still going is marked stale) and each session's AI watermarks. It also takes the applied What We Heard words off their steps (`private.heard_unapply`): the headline, number, source note and phone line go back to the template's step, which is a Draft again. Clear test answers (any engagement) deletes only the AI grid merges made by runs since the first test answer, in the steps its test answers touched, so a real merge from before the rehearsal stays; the rest of the AI records already clear with their answers. Migration `20261109040000_overnight_setup_reset.sql`; pgTAP in `practice_room.test.sql`.

An assigned facilitator or Clearway admin uses **Reset practice room**, then **Confirm reset** on the practice setup page. The database accepts no caller-supplied engagement id for reset. It soft-deletes practice attendees, requests and sign-in proofs, revokes practice device sessions, deletes only the Auth sessions bound to that practice engagement, and reopens it in setup status. It preserves the permanent engagement, facilitator assignments, audit rows, unrelated Auth sessions and Riverside’s eight people.

Guest grants and every practice proof/claim operation share a database advisory lock with reset. An in-flight claim cannot restore a revoked device after reset. Open phones discover the missing device, initialize a new device, and show the name form again. They can rejoin immediately. Nightly reset remains unimplemented: the tracked Vercel schedule runs check-ins only. The PRD's nightly reset is recorded in [remaining work](project-status.md).
